## 1. 正式構成（リクエスト経路）

```text
Browser
   ↓
Cloudflare Pages          ← 静的 GUI（public/）
   ↓
Pages Functions (BFF)     ← Auth / API 集約 / AI プロキシ / Health・OPS
   ↓
Cloudflare Tunnel         ← 非公開 Origin への到達（Access 併用可）
   ↓
EC2 API                   ← Python expect-ai（services/win5-ai）
   ↓
Prediction Core           ← AI_PLATFORM_ROOT + core-overlay
```

補助平面（同期的ユーザー経路の外側）:

```text
Collector（RC-1 コード同梱 / Real 本接続 HOLD）
Prediction（一覧・詳細・fallback 理由）
Operations（Result Automation / OPS Monitor / Evidence / Runbook）
```

## 2. レイヤ別責務

### 2.1 Browser

| 責務 | 内容 |
|------|------|
| 担当 | 利用者 UI の表示・操作 |
| 含む | ログイン / setup、レース一覧、予想表示、KAOBA 等の画面 |
| 含まない | 秘密鍵・DB・直接の EC2 アクセス |
| 依存 | Pages 配信の HTML/JS/CSS |

### 2.2 Cloudflare Pages

| 責務 | 内容 |
|------|------|
| 担当 | 静的アセット配信、カスタムドメイン |
| 含む | `public/`（GUI、`invitations.json` seed、β設定の公開面） |
| 含まない | 重い推論、永続 DB |
| 運用 | Deployment 成功確認、Rollback |

### 2.3 Pages Functions（BFF）

| 責務 | 内容 |
|------|------|
| 担当 | エッジ上の API ゲートウェイ |
| 含む | Auth（招待・ログイン）、契約ガード、`AI_BASE_URL` へのプロキシ、`/api/health`、`/api/ops/monitor` |
| 含まない | Prediction Core 本体、Collector 実行 |
| 設定 | `AUTH_MODE`、`AI_ENGINE`、Access Service Token、`OPS_MONITOR_KEY` 等（Secrets） |

### 2.4 Cloudflare Tunnel

| 責務 | 内容 |
|------|------|
| 担当 | BFF から EC2 AI への安全な到達 |
| 含む | `cloudflared-expect-ai`、内部ホスト名（例: `ai.expect-keiba.com`） |
| 含まない | ビジネスロジック |
| 障害時 | Tunnel 切断フロー（監視設計 §4.5） |

### 2.5 EC2 API

| 責務 | 内容 |
|------|------|
| 担当 | Python AI HTTP サービス（`expect-ai.service`） |
| 含む | `/health`、`/v1/predictions`、admin（ETL / results / monitoring）、Result Automation 連携 |
| データ | SQLite（`EXPECT_AI_DB_PATH`）、migrations 001–008 |
| デプロイ必須 | overlay 同期 → migrate → restart（Runbook） |

### 2.6 Prediction Core

| 責務 | 内容 |
|------|------|
| 担当 | 単勝・関連の推論・特徴読込・モデル経路 |
| 配置 | `/opt/expect-ai/platform`（`AI_PLATFORM_ROOT`）+ `platform/core-overlay` |
| 含む | FeatureLoader bridge、scoring / confidence overlay |
| 含まない（v1.0 製品） | RePick V2 作動（Flag OFF・未配線） |
| 品質 | `real_ai` / `mock_fallback`（不足時は理由付きフォールバック） |

## 3. ドメイン平面の責務

### 3.1 Collector

| 項目 | v1.0 の扱い |
|------|-------------|
| 責務 | 週次・平日分散の収集計画、Job/Manifest、Budget/Retry、Gate（設計どおり Prediction 非破壊） |
| 採用 | **RC-1 コード・Contract・DB schema 同梱** |
| 非採用 | **Real KeibaNet 本接続（HOLD）** |
| 実行 | 本番で Real 向け常時ジョブを回さない |
| 参照 | `services/win5-ai/app/data/collect/`、collector RC-1 docs |

### 3.2 Prediction

| 項目 | v1.0 の扱い |
|------|-------------|
| 責務 | レース単位の予想提供、fallback_reason、BFF 経由の一覧/詳細 |
| 入口 | Browser → BFF `/api/predictions` → EC2 → Core |
| 成功の定義（可用性） | HTTP 成功かつ `provider=python` |
| 品質課題 | `mock_fallback` 高比率は KI-01（1.1 でデータ充実） |

### 3.3 Operations

| 項目 | v1.0 の扱い |
|------|-------------|
| 責務 | 死活監視、結果自動化、障害対応、招待運用、月次報告 |
| 含む | Result Automation、OPS Monitor、Miss Evidence、Runbook、監視設計 |
| 含まない | 予想ロジックの実験的改変、HOLD 解除の独断 |
| 成果物 | `operations-runbook.md`、`v1.0-ops-monitoring-design.md`、月次テンプレ |

## 4. データと設定の所在（要約）

| 種類 | 所在 |
|------|------|
| GUI / 招待 seed | Pages `public/` |
| BFF 秘密情報 | Cloudflare Pages Secrets / vars |
| AI 環境変数 | EC2 `/opt/expect-ai/shared/.env` |
| Platform / Core | `/opt/expect-ai/platform` |
| アプリコード | EC2 `/home/ubuntu/KEIBA-Single-AI` @ `v1.0.0-stable` |
| DB | `EXPECT_AI_DB_PATH`（例: `.../var/expect_ai.db`） |
| 研究コード | リポジトリ `research/`（製品経路外） |

---

## 5. 境界ルール（v1.0）

1. Browser は EC2 に直接繋がない（BFF + Tunnel）  
2. Collector は Prediction Core を壊さない（非破壊・HOLD）  
3. Operations は Flag / HOLD ポリシーを監視し、無断 ON しない  
4. 構成変更は本 Snapshot を更新する **次バージョン**で行う（Freeze 参照）
