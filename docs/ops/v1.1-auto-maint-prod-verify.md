## 確認手順（短縮）

> UI の maintenance 判定は **認証完了後のみ**。未ログインで `/` に来た場合は必ず `login`（maintenance へ飛ばない）。  
> **`/login` は既ログインでも常にログイン画面を表示**（自動で maintenance へ飛ばない）。切替時は「ログアウトして切り替え」または再ログイン。

### ① ADMIN（既存本番 ADMIN・認証情報は本ドキュメントに記載しない）

1. 通常どおりログイン  
2. トップ / Race / Chat / Analysis が利用できる（maintenance に飛ばない）  
3. Prediction / Conversation が `OPS_CLOSED` にならない

### ② 一時ID → 上記「テスト用招待コード」

ログイン／初回設定完了の直後に `/maintenance` へ遷移すること。

### ③ USER → `cursor-review`

ログイン成功の直後に `/maintenance` へ遷移すること。

### ④ 手動優先（必要時のみ・確認後は必ず戻す）

| 設定 | 期待 |
|------|------|
| `maintenance_mode: true` | CLOSED / `manual_maintenance_mode` |
| `ops_mode: "CLOSED"` | CLOSED / `manual_ops_mode` |
| `ops_mode: "PUBLIC"` | PUBLIC（平日でも手動が勝つ） |
| 両方オフ・`ops_mode: null` | 平日なら auto_calendar CLOSED |

## Flag を false に戻す手順

1. `config/beta.json` と `public/config/beta.json` の  
   `ui_features.v11_auto_maintenance` を **`false`**  
2. `maintenance_mode` / `ops_mode` は触らない（確認で変えた場合は元に戻す）  
3. commit → `main` push および／または  
   `npx wrangler pages deploy public --project-name=keiba-single-ai --branch=main`  
4. 確認:

```bash
curl -sS -A "Mozilla/5.0" https://expect-keiba.com/config/beta.json | jq '.ui_features.v11_auto_maintenance'
# false

curl -sS -A "Mozilla/5.0" https://expect-keiba.com/api/ops/public-status | jq '.data.auto_maintenance_enabled, .data.ops_mode, .data.reason'
# false / PUBLIC / default_public（手動オーバーライド無し時）
```
