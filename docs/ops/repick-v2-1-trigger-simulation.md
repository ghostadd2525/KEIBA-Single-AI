## 0. 方法

1. V2.0 Treatment で発火した **100 レース**に対し、匿名条件 TN-A / TN-C / TN-D を事後判定する。
2. プロファイルは入れ子: `V2.0 ⊇ TN-A ⊇ TN-A+TN-C ⊇ TN-A+TN-C+TN-D`。
3. 各プロファイルで「発火するレース」だけ Treatment 結果を採用し、それ以外は **Control** 結果を採用する。
4. 狭化は発火を減らすだけなので、この合成は相互作用のない近似として妥当。

判定定義:

| 条件 | 定義 |
|------|------|
| TN-A | `surv_pos(cand) == N+1`（survival スコア降順の近似順位） |
| TN-C | `model_rank(victim) ≥ 11` |
| TN-D | 発火前 selected 内の `model_rank∈[7,10]` 頭数 `< 2` |

Control Hit（参考）: **215**  
注: survival 順位は `attach_world_survival_scores` 後の近似ソート。本番 `build_world_aware_repick_pool` の route swap 後順位と完全一致しない場合がある。

## 3. 寄与の分離（差分）

| ステップ | Δ発火 | ΔR_G1 | ΔG1_rescue | ΔHit | Δchurn_hit | Δchurn_g1 | Δchurn_race |
|----------|------:|------:|-----------:|-----:|-----------:|----------:|------------:|
| V2.0 → TN-A | -81 | -0.363636 | -4 | -5 | -61 | -76 | -0.28421 |
| TN-A → TN-A+TN-C | -7 | 0.0 | 0 | 0 | -6 | -7 | -0.024562 |
| TN-A+TN-C → TN-A+TN-C+TN-D | -9 | 0.0 | 0 | 0 | -7 | -9 | -0.031579 |

### 読み（改善率 vs churn）

1. **TN-A:** 発火 100→19（−81）。churn_hit 77→16（−61）。**R_G1 4→0、Hit 220→215（V2.0 の Hit改善 +5 が消滅）**。
2. **+TN-C:** 発火 19→12（−7）。churn_hit 16→10（−6）。R_G1 は 0 のまま。
3. **+TN-D:** 発火 12→3（−9）。churn_hit 10→3（−7）。R_G1 は 0 のまま。churn_race 0.042→0.011（Exit ≤0.05 を下回る）。

### 重要事実（寄与の分離）

V2.0 の **Hit改善 5 件**および **G1_rescue 4 件**は、いずれも近似 survival で **`delta = surv_pos − N = 2`（N+2）**。

| 集合 | n | TN-A（N+1）通過 |
|------|--:|----------------:|
| Hit改善（V2.0） | 5 | **0** |
| G1 かつ in_repick=1 | 4 | **0** |
| V2.0 発火 delta=1 | 19 | TN-A 集合 |
| V2.0 発火 delta=2 | 80 | TN-A で除外 |

| 軸 | 主に効く段 | 内容 |
|----|------------|------|
| **churn 削減** | **TN-A が最大** | −81 発火 / churn_hit −61 |
| **改善率** | 改善は **N+2 に集中** | TN-A 適用と同時に R_G1・Hit改善が消える |
| TN-C / TN-D | churn を追加削減 | 改善は既に 0 のためトレードオフなし |

**結論:** TN-A は既 Hit churn 削減に有効だが、**現行 V2.0 の改善率とは両立しない**（改善が N+2 側）。A+C+D は churn ゲートに近いが R_G1 は未達。
