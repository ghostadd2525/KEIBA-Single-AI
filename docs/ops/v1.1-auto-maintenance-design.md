# 自動開催日判定による平日メンテナンス — 設計書

**Status:** APPROVED — implementing on `feature/v1.1-ui-ops`  
**Baseline:** `v1.0.0-stable` 変更禁止 / Prediction Core・Collector・RePick 非変更  
**採用方針:** UI + API 両方 / ADMIN bypass 維持 / Flag 既定 `false`

---

## 1. アーキテクチャ

既存 OPS-1 / OPS-1A を拡張する。新規の別系統ゲートは作らない。

| 層 | 役割 |
|----|------|
| **CalendarProvider** | 開催日判定・次回公開日。OPS Mode 優先順位とは分離 |
| **resolveOpsModeDetailed** | 手動設定 →（Flag ON 時）自動判定 → PUBLIC |
| **Middleware** | USER + CLOSED → `OPS_CLOSED` 503。ADMIN bypass 不変 |
| **フロント Gate** | Flag ON かつ CLOSED なら `maintenance.html` へ誘導 |

営業時間外: EC2 / Collector / Pages は止めない。一般 USER の業務 API とアプリ画面だけ閉じる。

---

## 2. 判定フロー（優先順位）

1. 手動 `ops_mode`（明示 PUBLIC / CLOSED 等）
2. 手動 `maintenance_mode === true` → CLOSED
3. `ui_features.v11_auto_maintenance === true` のときのみ  
   `CalendarProvider.decide` で非開催日 → CLOSED（`reason: auto_calendar`）
4. それ以外 → PUBLIC

手動が最優先: `ops_mode: "PUBLIC"` なら平日でも強制公開。  
`ops_mode: "CLOSED"` または `maintenance_mode: true` なら土日でも強制クローズ。

タイムゾーン: 常に **Asia/Tokyo (JST)**。正本は BFF `/api/ops/public-status`。

---

## 3. CalendarProvider

- IF: `functions/_lib/calendar/CalendarProvider.js`（JSDoc 契約）
- 初期: `WeekendCalendarProvider`（土日 = 開催日、月〜金 = 非開催）
- Factory: `createCalendarProvider` — 将来 `ops-calendar` 差し替え口。既定は weekend
- クライアント薄いミラー: `public/assets/api/calendar-weekend.js`（status 失敗時のみ）

---

## 4. API 影響

- Flag OFF: 現行と 100% 同等
- CLOSED 時 USER: 既存どおり `503` + `OPS_CLOSED`
- CLOSED 対象: Prediction / Conversation / User ほか exempt 以外
- 利用可: Health / Login / 招待 / 静的 / メンテ画面 / `/api/ops/monitor` / **`GET /api/ops/public-status`**

---

## 5–7. BFF / フロント / Flag

- BFF: `opsMode.js` 拡張、calendar/*、`public-status.js`、`betaConfig` DEFAULTS
- フロント: `maintenance.html`、`auto-maintenance.js`、主要 HTML に gate
- Flag: `v11_auto_maintenance` 既定 **false**

### UI Gate タイミング（必須）

| 状態 | 遷移 |
|------|------|
| **未ログイン** | 常に `login.html`（Auto Maintenance で `maintenance.html` へ飛ばさない） |
| **ログイン成功後 ADMIN** | 通常画面（`index.html` 等） |
| **ログイン成功後 USER / 一時ID** | Flag ON かつ CLOSED なら即 `maintenance.html` |
| **判定タイミング** | **認証完了後のみ**（トークン無しでは `run()` は no-op） |

メンテ画面: メンテ中・次回公開・招待案内・会話型AI導線（CLOSED 時は「開催日に利用できます」）

Gate 除外: `login.html` / `setup.html` / `ops.html` / `terms.html` / `maintenance.html`  
`maintenance.html` 未ログイン時は `login.html` へ戻す。

**login 画面の扱い:** `/login` は Auto Maintenance の `run()` 対象外（SKIP）。  
既存トークンがあっても **自動で maintenance / index へ飛ばさない**（アカウント切替テスト用）。  
遷移は **ログイン / setup 成功時のみ** `goPostAuthLanding()`。任意の「ログアウトして切り替え」で明示 logout。

---

## 8. Canary

1. Flag OFF デプロイで差分なし  
2. ステージングで Flag ON  
3. 平日: メンテ画面・USER 503・health/login OK・ADMIN bypass  
4. 土日: 通常公開  
5. 手動上書き確認  
6. Flag OFF で即時ロールバック確認  

推奨順末尾: `auto_maintenance`

---

## 9. Rollback

| 段階 | 手順 |
|------|------|
| 即時 | `v11_auto_maintenance: false` |
| 強制公開 | `ops_mode: "PUBLIC"` |
| 強制クローズ | `maintenance_mode: true` または `ops_mode: "CLOSED"` |
| 最終 | コミット revert（`v1.0.0-stable` は動かさない） |

---
