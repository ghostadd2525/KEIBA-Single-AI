### 1.2 コンポーネント別詳細

#### Pages
- **目的:** ユーザー到達面の死活
- **正常:** トップ / `login` が 200
- **異常例:** 5xx、DNS 失敗、意図しないメンテ画面の常時表示（計画メンテ除く）

#### BFF（Pages Functions）
- **目的:** API ゲートウェイ・Auth・AI プロキシの死活
- **`/api/health`:** BFF 単体 + `ai_proxy_configured`
- **`/api/ops/monitor`:** 下流一括（python_api / tunnel / prediction / conversation / etl / result_automation）
- **異常例:** Functions 500、`ai_proxy_configured=false`（設定欠落）

#### EC2 API
- **目的:** Python AI プロセスの死活
- **正常:** `status=ok`、Tunnel 経由で到達
- **異常例:** systemd inactive、port 8000 拒否、overlay 未同期による起動ループ（KI-02）

#### Prediction
- **目的:** 予想業務の到達性（品質比率はダッシュボード側）
- **正常:** BFF 経由で一覧取得成功、`provider=python`
- **注意:** `mock_fallback` 多数は **単体では Critical にしない**（KI-01）。`provider=mock` / 全件失敗 / 5xx を優先検知

#### DB
- **目的:** SQLite（`EXPECT_AI_DB_PATH`）の利用可能性
- **間接監視:** AI health が ok ならプロセス視点では読める
- **直接確認（運用）:** ファイル存在、migration 表、ディスク残量（OS）
- **異常例:** DB ロック長時間、ファイル消失、migration 不整合

#### Result Automation
- **目的:** 結果取込・自動化パイプラインの健全性
- **正常:** `result_automation.status=ok`、重大 issue なし
- **異常例:** `failed_latest` 増加、`stale_active` 滞留、manifest/summary 欠落

### 1.3 推奨プローブ順序（障害切り分け）

```text
1. Pages HTML          → エッジ / DNS
2. BFF /api/health     → Functions
3. AI /health (public) → Tunnel + EC2
4. EC2 local health    → プロセス単体
5. /api/predictions    → 業務 API
6. result_automation   → 運用ジョブ
7. DB / migrations     → 永続化
```

## 2. 運用ダッシュボード設計

### 2.1 目的・利用者

| 項目 | 内容 |
|------|------|
| 利用者 | 運用担当（日次）、インシデント対応者 |
| 更新頻度 | リアルタイム相当: 1–5 min プローブ / 日次集計 / 月次レポート |
| v1.0 実現手段 | **手動シート or 既存 JSON 応答の記録** + Cloudflare / journal 目視。専用 UI 実装は 1.1（B1.1-05） |

### 2.2 画面構成（論理）

```text
┌─────────────────────────────────────────────────────────┐
│  Expect Ops — v1.0.0-stable                    [環境]   │
├──────────────┬──────────────┬──────────────┬────────────┤
│ Overall      │ Latency      │ Errors       │ Quality    │
│ 緑/黄/赤     │ p50/p95      │ 5xx / fail%  │ fallback等 │
├──────────────┴──────────────┴──────────────┴────────────┤
│ Health strip: Pages | BFF | EC2 | Pred | DB | RA         │
├─────────────────────────────────────────────────────────┤
│ Trends (24h / 7d): 応答時間・エラー率・mock_fallback率   │
│                    AI成功率・Prediction件数・Login成功率 │
├─────────────────────────────────────────────────────────┤
│ Active Alerts | 直近インシデント | Baseline / Flag 状態   │
└─────────────────────────────────────────────────────────┘
```

### 2.3 指標定義

| 指標 | 定義 | 取得元（現状） | 表示 |
|------|------|----------------|------|
| **API 応答時間** | BFF 主要 API の応答時間。優先: `/api/health`, `/api/predictions`, `/api/ops/monitor`。可能なら p50/p95 | プローブ計測（curl 時間）、将来 `var/ops/metrics.jsonl` / CF Analytics | 時系列 + 最新 |
| **エラー率** | 対象 API の非 2xx または `ok=false` 件数 / 試行件数（窓: 15 min / 24 h） | プローブ結果、Workers ログ、journal | % + 件数 |
| **mock_fallback 率** | `engine_source=mock_fallback` 件数 / Prediction 一覧件数 | `GET /api/predictions` の `meta.items[]` | %（KI-01 注記付き） |
| **AI 成功率** | `engine_source=real_ai` 件数 / 一覧件数（＝ 1 − mock_fallback率 ※他 source がある場合は明示） | 同上 | % |
| **Prediction 件数** | 一覧の件数（`items` 長または `data` 長） | 同上 | 件数（急減を検知） |
| **Login 成功率** | 窓内の成功ログイン / 試行。v1.0: **招待 start 成功 + setup/login API 成功**を代理指標可 | `/api/auth/invite/start`（運用テスト）、`/api/auth/login`、監査 JSONL（あれば） | % + 失敗理由 |

### 2.4 補助表示（必須）

| 項目 | 理由 |
|------|------|
| Baseline tag / デプロイ SHA | 意図しない差分検知 |
| `WIN5_REPICK_*` 未設定 | Flag 運用ルール遵守 |
| `EXPECT_KEIBANET_*` 未設定 | Real KeibaNet HOLD |
| Result Automation issues 件数 | HC-A01/A02 |
| `provider` / `engine` | mock プロバイダ化の早期発見 |

### 2.5 しきい値（ダッシュボード色）

| 指標 | 緑（正常） | 黄（注意） | 赤（異常） |
|------|------------|------------|------------|
| API 応答時間 p95（predictions） | < 3 s | 3–8 s | > 8 s またはタイムアウト |
| エラー率（15 min） | < 1% | 1–5% | > 5% または連続失敗 |
| mock_fallback 率 | 監視のみ※ | 急騰（前日比 +20pt 等） | **provider≠python** または件数 0 |
| AI 成功率（real_ai） | 監視のみ※ | 急落 | real_ai=0 かつ provider=python が継続（データ全欠の可能性） |
| Prediction 件数 | 前日比 ±30% 以内 | ±30–70% | 0 または −70% 超 |
| Login 成功率（運用窓） | ≥ 95% | 80–95% | < 80% または start 連続失敗 |

※ v1.0 時点の絶対 `mock_fallback` 高水準は **KI-01 既知**。絶対値での赤点灯はせず、**変化率・provider・可用性**で赤にする。

## 3. Alert 条件

### 3.1 深刻度定義

| レベル | 意味 | 応答目標（目安） | 通知 |
|--------|------|------------------|------|
| **Critical** | ユーザー影響大 / サービス停止相当 | 15 分以内に着手 | 即時（電話/チャット必須） |
| **Warning** | 劣化・部分障害・HOLD 違反の兆候 | 営業時間 2 時間 / 開催日は 30 分 | チャット |
| **Info** | 把握事項・デプロイ・既知変動 | 日次レビュー | ログ / 日次ダイジェスト |

### 3.2 Critical

| ID | 条件 | 想定原因 | 初期対応 |
|----|------|----------|----------|
| C-01 | Pages または BFF `/api/health` が **5 分間で 3 回連続失敗** | Pages / Functions 障害 | §4 Pages |
| C-02 | 公開 AI `/health` **到達不可**が 3 分継続 | Tunnel / EC2 / プロセス | §4 Tunnel or AI |
| C-03 | `expect-ai` が **inactive** または起動ループ | overlay / コード / DB | §4 AI・Runbook overlay |
| C-04 | `/api/predictions` が **5xx または ok=false** 連続 | AI / BFF プロキシ | §4 API |
| C-05 | `meta.provider` が **python 以外**に変化（意図変更なし） | `AI_BASE_URL` 欠落等 | Tunnel / Pages secrets |
| C-06 | DB ファイル消失・health が DB 原因で継続失敗 | ディスク / パス誤設定 | §4 DB |
| C-07 | ログイン / invite start が **全失敗**（運用確認で再現） | Auth / 招待 seed / メンテ誤 ON | Pages Rollback / メンテ確認 |

### 3.3 Warning

| ID | 条件 | 備考 |
|----|------|------|
| W-01 | predictions p95 > 3 s が 15 分継続 | 過負荷・下流遅延 |
| W-02 | エラー率 1–5%（15 min） | 部分障害 |
| W-03 | `result_automation.issues` 非空、または failed/stale 増加 | RA 劣化 |
| W-04 | Prediction 件数の急減（−30% 超） | カタログ / 供給 |
| W-05 | `mock_fallback` 率が前日比 **+20 ポイント以上** | データ悪化（KI-01 の急変） |
| W-06 | `real_ai` が 0 件だが API は 200 / provider=python | 供給全欠の疑い |
| W-07 | `cloudflared` active だが間欠的 timeout | Tunnel 不安定 |
| W-08 | 本番 `.env` に `WIN5_REPICK_*` または `EXPECT_KEIBANET_*` を検出 | **ポリシー違反**（HOLD/Flag） |
| W-09 | schema_migrations が Baseline 期待と不一致 | デプロイ手順漏れ |

### 3.4 Info

| ID | 条件 |
|----|------|
| I-01 | デプロイ完了（Pages / EC2 checkout） |
| I-02 | 計画メンテナンス ON/OFF |
| I-03 | 招待 ID 追加と Pages 再デプロイ |
| I-04 | 月次レポート作成 |
| I-05 | KI-01 水準の `mock_fallback` 高止まり（急変なし） |
| I-06 | Real KeibaNet / RePick が HOLD/OFF のままであることの週次確認 OK |

### 3.5 抑制ルール

- 計画メンテ中は C-01/C-07 を抑制（メンテ告知 Info を先行）
- KI-01 の高 `mock_fallback` 絶対値だけでは Critical にしない
- 同一原因の連続アラートは 15 分に 1 回まで集約

## 4. 障害対応フロー

共通: **発見 → 深刻度判定 → 被害止め → 切り分け → 復旧 → 記録 → 再発防止**  
詳細手順の正本: [`operations-runbook.md`](./operations-runbook.md) · [`../rollback-runbook.md`](../rollback-runbook.md)

### 4.1 API 停止（BFF / Predictions 5xx・タイムアウト）

```text
[検知] C-01 / C-04 / エラー率 Critical
   │
   ├─ /api/health 失敗？ ──Yes──► Pages / Functions 障害として 4.4 へ
   │
   No
   ├─ /api/health OK かつ /api/predictions 失敗
   │     ├─ AI /health 失敗？ ──Yes──► 4.3 AI or 4.5 Tunnel
   │     └─ AI OK ──► BFF プロキシ・契約検証・ログ確認
   │                    必要なら Pages Rollback
   │
   └─ 被害止め: 必要なら maintenance_mode=true
```

**復旧確認:** health → predictions 200 → provider=python

### 4.2 DB 障害

```text
[検知] C-06 / health 失敗 / sqlite エラー in journal
   │
   ├─ プロセスは生きているが読取失敗 → ディスク・権限・パス確認
   ├─ DB ファイル消失 → バックアップからリストア（勝手に空 DB で上書きしない）
   ├─ ロック・破損疑い → サービス停止 → バックアップ確保 → リストア → migrate 確認 → restart
   └─ migration 不整合 → Runbook §3 / バックアップ方針
```

**復旧確認:** health ok、`schema_migrations`、predictions サンプル

### 4.3 AI 停止（expect-ai inactive / 起動ループ）

```text
[検知] C-02 / C-03
   │
   ├─ journal に feature_loader ModuleNotFound？
   │     └─ Yes → overlay 同期（Runbook §2）→ restart（§4）
   ├─ その他 ImportError / Traceback → 直近デプロイ差分確認
   │     └─ 必要なら git checkout v1.0.0-stable → overlay → migrate → restart
   └─ OOM / ディスク → OS リソース確保後に restart
```

**復旧確認:** local + public health、`result_automation` キー、predictions

### 4.4 Pages 障害

```text
[検知] C-01 / 静的 5xx / ログイン不可
   │
   ├─ Dashboard で最新 Deployment 失敗？ → 前 Success へ Rollback
   ├─ メンテ誤 ON？ → beta.json 確認・修正・再デプロイ
   ├─ 招待 seed 欠落のみ？ → invitations.json + 再デプロイ（API は生きている場合あり）
   └─ 広域 CDN 障害疑い → ステータス確認・案内（Info/Critical は影響範囲で）
```

**復旧確認:** HTML 200、`/api/health`、login/setup 到達

### 4.5 Tunnel 切断

```text
[検知] 公開 AI /health 失敗、EC2 local health は成功（典型）
   │
   ├─ systemctl status cloudflared-expect-ai
   ├─ restart cloudflared-expect-ai
   ├─ なお失敗 → トークン・DNS・Access Service Token（Pages 側）確認
   └─ local も失敗なら 4.3（AI 本体）を優先
```

**復旧確認:** `https://ai.expect-keiba.com/health`、BFF predictions の provider=python

### 4.6 対応後の必須記録

| 項目 | 内容 |
|------|------|
| 検知時刻 / 解消時刻 | UTC または JST 明示 |
| Alert ID | C-xx / W-xx |
| 影響 | ログイン不可、予想不可 等 |
| 実施コマンド要約 | overlay / rollback / restart 等 |
| 再発防止 | Runbook 追記・1.1 Backlog 化 |
