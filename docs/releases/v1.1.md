# Release v1.1 — PI Prediction API 本番移行

**リリース日:** 2026-07-21  
**前提:** v1.0（Race Catalog PI 連携）が本番稼働済みであること

---

## 追加機能

- **PI Prediction プロキシ（BFF）**  
  `GET /api/predictions/{race_id}` および `GET /api/predictions?date=...` が、Cloudflare Pages BFF 経由で PI KeibaNet API `GET /v1/predictions/{race_id}` を呼び出す。
- **PI race_id を正式キーとして統一**  
  例: `2026-07-25-01-06`（Win5 形式）。Prediction 画面 URL・API 契約ともにこの ID を使用する。
- **PI → PredictionBundle マッパー**  
  `functions/_lib/piPredictionMapper.js` が PI 応答（candidates / overall_confidence）を `single-prediction-bundle/2.0` に投影する。
- **契約テスト**  
  `tests/contract/pi-prediction.test.mjs` でマッピングと `engine_source=pi` を検証。
- **E2E スクリプト**  
  `scripts/e2e-pi-prediction.mjs` で PI 直叩き smoke を実行可能。

---

## 変更点

| 領域 | 内容 |
|------|------|
| BFF | `predictionAdapter.js`: `PI_BASE_URL` 設定時は PI のみ使用。**mock_fallback 廃止** |
| 一覧 API | mock カタログ（`/data/mocks/races.json`）を参照しない。PI `/v1/races` → 各 `/v1/predictions/{race_id}` |
| メタデータ | 成功時 `meta.engine_source = "pi"`, `provider = "pi"`, `engine = "real"` |
| Tunnel | `ai.expect-keiba.com/v1/predictions` → EC2 `:8081`（PI API）。定義: `infra/cloudflare/tunnel-ai-ingress.json` |

### v1.0 からの継続

- Race Catalog（`GET /api/races`）は引き続き PI `/v1/races` プロキシ（v1.0 実装）。
- フロントエンド契約（`race.html?race_id=...`）は変更なし。

---

## Breaking Changes

**なし（クライアント契約）**

- API パス・レスポンススキーマ（PredictionBundle）は v1.0 と同一。
- 変更があるのは **内部ソース** のみ（mock / win5-ai フォールバック → PI 実データ）。

**運用上の注意（Breaking に近い挙動変化）**

- `PI_BASE_URL` 未設定環境では、本番同等の Prediction は取得できない（mock アセットへのサイレントフォールバックは **行わない**）。
- PI 側で `prediction_available: false` のレースは BFF が **404** を返す（ダミー Prediction は返さない）。

## 運用方法

### 必須 Secrets（Cloudflare Pages · Production）

| Secret | 例 | 用途 |
|--------|-----|------|
| `PI_BASE_URL` | `https://ai.expect-keiba.com` | Race Catalog + **Prediction** |
| `AI_BASE_URL` | `https://ai.expect-keiba.com` | win5-ai（分析・Kaoba 等。Prediction 本体は PI 優先） |

### Tunnel ルート（EC2）

`infra/cloudflare/tunnel-ai-ingress.json` を参照。最低限:

- `/v1/races` → `127.0.0.1:8081`（PI API）
- `/v1/predictions` → `127.0.0.1:8081`（PI API） ← **v1.1 で追加**
- その他 → `127.0.0.1:8000`（win5-ai）

### デプロイ

```bash
git push origin main          # Pages 自動デプロイ
# または手動:
npx wrangler pages deploy public --project-name keiba-single-ai --branch main
```

### 本番確認コマンド

```bash
# 1件（admin トークン要）
curl -sS "https://expect-keiba.com/api/predictions/2026-07-25-01-06" \
  -H "Authorization: Bearer $TOKEN" | jq '.meta.engine_source'
# 期待: "pi"

# 一覧
curl -sS "https://expect-keiba.com/api/predictions?date=2026-07-25" \
  -H "Authorization: Bearer $TOKEN" | jq '.meta.engine_source, (.data|length)'
# 期待: "pi", 9
```

### ローカル E2E

```bash
PI_BASE_URL=http://127.0.0.1:8081 node scripts/e2e-pi-prediction.mjs
node --test tests/contract/pi-prediction.test.mjs
```

## 今後の課題

1. **一覧カードの AI 信頼度** — `races.html` は Race Catalog のみ参照のため、カード上の信頼度が 0% 表示のまま。Prediction 一覧 API との統合または軽量メタ付与が必要。
2. **Prediction 理由・展開テキスト** — PI Core 出力に narrative / reasons が薄い場合、UI は「理由データなし」となる。win5-ai explain 連携は v1.2 候補。
3. **一覧 API レイテンシ** — 日付指定時に PI predictions を逐次取得（最大 9 並列相当）。キャッシュ（KV / `Cache-Control`）の検討。
4. **race_id 双方向 trace** — `numeric_race_id` / `collector_race_id` を BFF meta に露出済み。win5-ai 分析画面との ID 統一（v1.0 未着手 D 項目）を継続。
5. **PI 未公開レース** — `prediction_available: false` 時の UX（503 vs 404 メッセージ整備）。
